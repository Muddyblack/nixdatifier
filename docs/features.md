# Features

- **Generations** — A timeline of your system generations with the booted and next-boot ones highlighted, added / removed / changed package counts, kernel and NixOS release badges, and search across numbers, dates, and package names.
- **Generation actions** — Activate a generation now, set it for next boot, or delete it (through Polkit/`pkexec`). The booted and next-boot generations are protected, and confirmations are configurable.
- **Package changes** — Expand any generation to see what changed against the previous one (or the booted one), with versions, size deltas, store paths, app icons, and homepage links. **Why is this here?** on a package shows the dependency chain from the system down to it (like `nix why-depends`) and what pulls it in: an `environment.systemPackages` entry, a service, Home Manager, `/etc` or the system itself; "Show all" lists one chain per such origin.
- **Several machines** — A flake with more than one `nixosConfigurations` machine adds a host picker to the header (and *Hosts* to the interactive view); one machine shows nothing new. It lists each host's state (online, offline, unreachable, auth needed), booted and next-boot generation, pending reboot, the flake revision it runs against your HEAD ("2 commits behind") and when it was last seen. Choosing a host re-scopes Generations, Compare, Health and the Store card over ssh (read-only helpers, your keys or agent, never a password, a timeout), and switch, boot, delete, cleanup and rebuild act there, naming the host in the confirmation. `nixdatifier --host NAME …` does the same from a terminal. See [Command line](cli.md#several-machines-one-flake).
- **Compare** — Diff any two generations with `nix store diff-closures`.
- **Configuration changes** — When your config lives in a Git repository, each generation records its commit, so you can see the `.nix` changes between generations.
- **Flake updates** — Checks your flake inputs against their upstream repositories, notifies you of updates, and can preview the resulting package changes (`nix build --dry-run`, lock file untouched) together with the cost: download and unpacked size, and how many derivations must be built locally because the binary cache has no build for them (flagged, as are downloads above a configurable threshold) or update a single input. Once the running system was scanned for vulnerabilities, the preview also says which known CVEs the update fixes and which it introduces. Expanding an input shows what changed upstream: GitHub releases with their notes, the newest commits, and a link to the full diff (set `GITHUB_TOKEN` to lift GitHub's anonymous limit of 60 requests per hour).
- **Tools**
  - **Secrets** — Deployed secrets (`/run/secrets`, `/run/agenix.d`) and your encrypted source file: format, recipients, freshness.
  - **Hash calculator** — Hashes for URLs, archives, GitHub revisions, local files, and store paths, in both Nix and SRI form, with a ready-to-paste fetcher snippet.
  - **Rebuild history** — The output of past switches, cleanups, flake updates, and custom commands, kept after the notification is gone.
  - **Store usage** — Why a store path cannot be garbage-collected: its GC roots, referrers, and closure size, and why it is in the running system.
- **Persistent folders** — A dedicated tab that appears on systems with [impermanence](https://github.com/nix-community/impermanence) (a root that is wiped on every boot, detected from the mounts). Three views:
  - **Folders** — everything your configuration persists (VS Code, Firefox, SSH keys, …) with friendly names, sizes and last change; search, filter by Home/System, sort by size, recency or name. Click a folder to look inside, with Back and breadcrumbs; filter by age, executables, unusual permissions or hidden names, tick several items and delete them in one go.
  - **Cleanup** — separate groups for caches, Trash, temporary and backup files, logs and crash reports, and personal files that have not changed in months. Each group explains what deletion means; tick, review, delete.
  - **Security** — autostart hooks, setuid files, programs in data folders and names made to hide, grouped into Check now / Review / Notes, with an optional ClamAV deep scan.

  Rows show Queued or Deleting until the helper confirms success; failures stay beside the affected item for review and retry. Further deletes queue up without waiting for a re-scan. One walk measures a folder and the level below it, so stepping down and back up is instant; leaving a folder stops its walk. Scan and Cleanup cover the persistent folders and /home; separate data disks join only when enabled in the settings. Deletes are refused for keys, SSH/GnuPG folders, and anything your configuration binds into the system. Disk usage sits behind one button in the header, with one bar per filesystem. Folder navigation stays visible while scrolling, with search and a sorting menu both in the kept list and inside folders. When no individual entries are detected, persistent roots can be opened directly. Tabs, rows and selection boxes support keyboard navigation.
- **Nix store** — Logical store size and estimated reclaimable contents from Nix’s database, free disk space, and cleanup (plus your own cleanup command). Both size figures use NAR bytes; shared files, compression, and snapshots mean actual reclaimed disk space can differ. Plain GC keeps generations; the other options explicitly remove old generations before collecting. **Deduplication** shows whether Nix links identical files on its own (`auto-optimise-store` or the `nix-optimise` timer), a rough estimate of what a run would free (sampled from about 1000 store paths, so it varies), and the last run's result; *Optimise store* runs `nix-store --optimise` after asking, with progress in the footer and the freed space in History. When neither is on, a copyable `nix.settings.auto-optimise-store = true;` is suggested.
- **Rebuild** — Footer *Rebuild ›* opens a panel with Switch, Boot, Test and Dry build. Your command labelled `rebuild` always wins and runs unchanged; otherwise `nh` (if installed), else `nixos-rebuild`. Choose *External terminal* (interactive) or *Built-in output panel* (live log, footer progress bar for derivations built and paths fetched, *Copy log* on failure). A rebuild started from a terminal shows its progress in the window too.
- **Custom commands** — Up to four terminal commands (for example `nixos-rebuild switch`) in the footer Commands panel. The widget follows the command until it actually exits.
- **Dev environments** — Point it at any project folder (or pick one direnv already knows) to see whether its `.envrc` is allowed, what it loads (`use flake`, `use nix`, `dotenv`, …), how old the cached environment is, the flake's inputs and how stale they are, and its `devShells` (click one to list its packages). Buttons run `direnv allow`, open a terminal inside the environment, or run `nix flake update`. It can also measure how much store space each project's `.direnv` cache keeps alive and clear it. Nothing in it is specific to NixOS.
- **System health** — A quick check of what quietly goes wrong: a pending reboot (running kernel older than the activated one), a nearly full `/boot`, a NixOS release close to end of life, unreachable or slow binary caches, and failed systemd units, plus your Nix version, Home Manager and `nix profile` generations. With [vulnix](https://github.com/nix-community/vulnix) installed (or *Run vulnix with nix run* on), it also lists **known vulnerabilities** in the running system: counts by severity, then each affected package with its CVEs (click one for the NVD advisory). The first scan, started by hand, downloads the NVD database; after that the tab scans on its own when the last scan is a day old or the system changed. A vulnix whitelist is respected. Without a scanner, none of this is shown.
- **Empty-state diagnosis** — When Generations stays empty, or Updates has nothing to check, the view lists what was checked instead of a blank space: NixOS or Nix on another distribution, the required tools, the Nix store, `/nix/var/nix/profiles` (missing or a permission problem), the generation list, the flake path, flake or channels setup (and which features channels support), flakes being enabled and untracked files in a git flake. Each failure has a fix, a copyable command, and the command that failed with its output; *Copy report* puts the whole list on the clipboard for a bug report. `nixdatifier doctor` prints the same checklist.
- **Any desktop** — A standalone app (window plus tray icon) needs only Qt, so it runs on GNOME, COSMIC, Sway, niri, XFCE, KDE, and X11. The same interface also runs as a Plasma widget and as a Quickshell popup with a panel pill. See [Hosts](hosts.md).
- **Appearance** — Accent and timeline colors, background color and opacity, corner radius, font scale, icon style, glow, and motion (all animations can be turned off).
